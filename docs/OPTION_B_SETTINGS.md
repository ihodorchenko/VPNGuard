# Вариант B — управление защищаемыми хостами через Settings

## Статус

Базовая версия варианта B **уже реализована** в текущей ветке.

Документ фиксирует:

- как устроено поведение сейчас;
- какие ограничения остались;
- что можно улучшить позже, не переходя на вариант A (JSON-конфиг + hot reload).

---

## 1. Цель

Дать пользователю возможность менять список защищаемых хостов **без пересборки приложения**, через нативное окно Settings.

Важно: PF-фаервол блокирует IP-адреса, а не URL. Поэтому настраиваются домены, IP-адреса или подсети, но не отдельные пути вида `https://example.com/api`.

---

## 2. Что уже реализовано

### 2.1. Окно Settings

Файл: `VPNGuard/Settings/SettingsView.swift`

- Секция **VPN Interface**: префикс интерфейса и точное имя интерфейса.
- Секция **Protected Hosts**:
  - многострочный редактор, один хост на строку;
  - кнопка **Save Hosts**;
  - кнопка **Reset to Defaults**;
  - индикатор сохранения;
  - сообщение с количеством сохранённых хостов и активных IP;
  - live-валидация: невалидные строки показываются оранжевым списком;
  - подсказка про игнорирование схем, путей и портов;
  - лимит — 32 хоста.
- Секция **Startup**: автозапуск защиты.
- Секция **About**: версия берётся из `CFBundleShortVersionString`.

### 2.2. Парсер и валидация

Файл: `Shared/ProtectionHostParser.swift`

Правила обработки:

- пустые строки игнорируются;
- строки, начинающиеся с `#`, считаются комментариями;
- inline-комментарии после `#` отбрасываются;
- схема (`https://`, `http://`) удаляется;
- путь, query и fragment удаляются;
- порт удаляется, если он валиден (1–65535);
- хост приводится к нижнему регистру;
- висящие точки удаляются;
- дубликаты удаляются с сохранением порядка;
- принимаются:
  - доменные имена (`claude.ai`, `api.anthropic.com`);
  - IPv4 (`192.168.1.10`);
  - IPv6 в скобках и без (`[2001:db8::1]:443`, `2001:db8::1`);
- отклоняются:
  - невалидные имена (`bad_host`, `-bad.com`, `bad-.com`, `exa..mple.com`);
  - невалидные порты (`example.com:0`, `example.com:notaport`);
  - CIDR (`10.0.0.0/8`) — в варианте B не поддерживается;
  - всё, что выходит за лимит 32 хоста.

Результат парсинга:

```swift
struct ProtectionHostParseResult {
    let hosts: [String]      // нормализованные валидные хосты
    let invalid: [String]    // строки, которые были отклонены
}
```

### 2.3. Хранение и применение

Файл: `VPNGuard/Protection/Rules.swift`

- Список хранится в `UserDefaults` по ключу `protectedHosts`.
- При старте старые значения мигрируются:
  - URL превращаются в хосты;
  - регистр нормализуется;
  - дубликаты удаляются.
- `updateHosts(_:)`:
  - сохраняет список;
  - дожидается DNS-refresh;
  - возвращает актуальный набор IP.
- `refresh()` резолвит все хосты **параллельно** через `TaskGroup`, чтобы таймаут DNS не умножался на количество хостов.

`ProtectionEngine` подписан на `Rules.$protectedIPs`: если блокировка активна, новые IP автоматически уходят в PF.

### 2.4. Мониторинг VPN

Файл: `VPNGuard/VPN/VPNMonitor.swift`

- Проверки `route -n get` для всех хостов выполняются параллельно.
- Если хотя бы один хост не идёт через VPN, состояние считается `disconnected`.

### 2.5. Диагностика

Файлы: `VPNGuard/Settings/DiagnosticsService.swift`, `VPNGuard/Settings/HelpView.swift`

- Help-панель больше не зашита на `claude.ai` и `api.anthropic.com`.
- Проверяются все хосты из текущего списка.
- HTTP-проверки выполняются параллельно.
- Команды для Terminal генерируются по актуальному списку.

### 2.6. Открытие Settings

Файл: `VPNGuard/App/AppDelegate.swift`

- Приложение переведено на AppKit-lifecycle (`@main AppDelegate`).
- macOS 26+:
  - Settings-сцена добавляется через `NSHostingSceneRepresentation`;
  - открывается через `representation.environment.openSettings()` — это действие, которое использует `SettingsLink` внутри.
- macOS 14–15:
  - используется `SettingsWindowController`, который показывает `SettingsView` в обычном `NSWindow`.
- Устаревшие селекторы `showSettingsWindow:` / `showPreferencesWindow:` больше не используются.

## 3. Ограничения варианта B

- Список хранится только в `UserDefaults` конкретного пользователя.
- Нет внешнего файла конфигурации и hot reload — это вариант A.
- Нельзя импортировать/экспортировать список.
- Нет отдельных статических IP/CIDR.
- CIDR намеренно отклоняется.
- Нет включения/отключения отдельного хоста.
- Нет отображения resolved IP и статуса route прямо в Settings (только в Help).
- Жёсткий лимит — 32 хоста.
- Блокировка работает по IP, поэтому URL с путями не поддерживаются.

## 4. Возможные улучшения в будущем

### 4.1. Структурированный редактор хостов

Вместо `TextEditor`:

- список строк с кнопками `+` / `−`;
- drag-and-drop для порядка;
- поиск/фильтр при большом списке;
- отдельная строка для добавления;
- сохранение по кнопке или автоматически.

Текущий текстовый редактор можно оставить как «Advanced mode».

### 4.2. Статус по каждому хосту в Settings

Показывать рядом с хостом:

- последний resolved IP;
- время последнего DNS-refresh;
- идёт ли трафик через VPN;
- последнюю ошибку.

Для этого `Rules` может публиковать `[String: HostStatus]`.

### 4.3. Импорт и экспорт

- экспорт списка в `.txt` или `.json`;
- импорт с валидацией и показом отклонённых строк;
- копирование списка в буфер обмена.

### 4.4. Отдельный список IP/CIDR

Добавить секцию `extraIPs`:

- строгая валидация IPv4/IPv6/CIDR;
- передача CIDR в `PFRuleBuilder` без DNS;
- защита от инъекций в текст PF-правил.

Это потребует изменений в `Rules`, `PFRuleBuilder` и, возможно, в `HelperTool`.

### 4.5. Включение/отключение отдельных хостов

Модель:

```json
[
  { "host": "claude.ai", "enabled": true },
  { "host": "chatgpt.com", "enabled": false }
]
```

Потребуется миграция `[String]` → структура и обновление `Rules`.

### 4.6. Улучшение сообщений валидации

- показывать номер строки;
- объяснять причину отказа;
- подсвечивать конкретную строку в редакторе.

### 4.7. Тесты

- вынести DNS-резолвер за протокол и протестировать `Rules.updateHosts`;
- тесты миграции старых значений `UserDefaults`;
- тесты лимита хостов;
- UI-тесты сохранения/сброса.

### 4.8. Переход на вариант A

Когда понадобится внешнее управление:

- `UserDefaults` заменить на `~/Library/Application Support/VPNGuard/config.json`;
- `SettingsView` станет редактором этого файла;
- добавить file watcher и hot reload;
- `ProtectionHostParser` уже готов к переиспользованию.

## 5. Критерии готовности будущих улучшений

- Изменения применяются без перезапуска приложения.
- Валидные хосты сохраняются, даже если часть строк невалидна.
- Невалидные строки не попадают в DNS и PF.
- Дубликаты и регистр нормализуются.
- При активной блокировке новые IP попадают в PF автоматически.
- Список сохраняется между запусками.
- Help-панель проверяет тот же список.
- Нет регрессии для macOS 14–15 и macOS 26+.

## 7. Ручной чек-лист

1. Открыть **Settings…** из меню — окно появляется на macOS 26+ и на macOS 14–15.
2. Добавить `chatgpt.com`, нажать **Save Hosts** — сообщение показывает активный IP set.
3. Ввести `bad_host` — строка появляется в «Ignored entries».
4. Ввести больше 32 хостов — лишние попадают в «Ignored entries».
5. Отключить VPN при включённой защите — PF-правила обновляются под новый список.
6. Перезапустить приложение — список сохраняется.
7. Открыть Help → **Запустить проверку** — проверяются новые хосты.

---

## 8. Не входит в вариант B

- Блокировка по URL-путям.
- Remote-конфиг и MDM.
- Многоуровневые профили правил.
- Автоматическое обновление списка с сервера.

Эти задачи логичнее делать поверх варианта A или отдельного конфигурационного слоя.
